### 2. Исправления кода 🔧

#### Файл: `src/engine/CorrelationEngine.cpp`

**Добавлено:**
```cpp
// === Автоматическое создание алертов для high/critical событий ===
QString sev = event.severity.toLower();
if (sev == "high" || sev == "critical") {
    Alert alert;
    alert.id = QUuid::createUuid().toString(QUuid::WithoutBraces);
    alert.title = "Высокоприоритетное событие: " + event.eventType;
    alert.description = QString("Автоматически созданный алерт для события с серьезностью '%1'\n"
                               "Устройство: %2\n"
                               "Тип события: %3\n"
                               "Действие: %4\n"
                               "Лог: %5")
                      .arg(event.severity)
                      .arg(event.deviceName)
                      .arg(event.eventType)
                      .arg(event.action)
                      .arg(event.rawLog);
    alert.severity = event.severity;
    alert.status = "open";
    alert.deviceName = event.deviceName;
    alert.triggeredAt = event.timestamp.isValid() 
                      ? event.timestamp 
                      : QDateTime::currentDateTimeUtc();
    alert.ruleId = "";
    alert.assignedTo = "";
    alert.comment = "Авто-создан (severity=" + event.severity + ")";

    if (m_db->createAlert(alert)) {
        qDebug() << "[CorrelationEngine] Auto-alert created for HIGH/CRITICAL event:"
                 << event.deviceName << "severity=" << event.severity;
        emit alertCreated();
    }
}
```

**Что это делает:**
1. Проверяет severity каждого события после создания
2. Если severity = "high" или "critical", автоматически создает алерт
3. Алерт наследует все параметры события (устройство, тип, серьезность)
4. Алерт имеет статус "open" (открытый) и требует немедленного внимания
5. Запись в логи для отладки

## 📊 Функциональная архитектура

### Поток обработки событий:

```
Внешний источник (simulator.py, attack_simulator.py)
        ↓
   WebSocket (порт 8080/8443)
        ↓
WebSocketWorker::onTextMessageReceived()
        ↓
DatabaseService::createEvent()  ← Сохранение в БД
        ↓
CorrelationEngine::analyze()
        ├─ Проверка правил корреляции (threshold, correlation)
        │  └─ Создание алерта ПО ПРАВИЛУ (если сработало)
        └─ Проверка severity
           └─ Создание алерта (если high/critical) ← НОВОЕ
        ↓
Alert::create() в БД
        ↓
broadcastJson() - отправка события всем WebSocket клиентам
        ↓
Web-интерфейс обновляет список алертов в реальном времени
```

## 🔐 Безопасность

### Принцип least privilege:
- ✅ События создаются **только** через WebSocket (с HMAC-подписью)
- ✅ Невозможно создать событие через HTTP API
- ✅ Алерты создаются **только** сервером (движком корреляции)
- ✅ Клиенты могут только менять статус алертов (open → investigating → closed)

### Защита от replay-attack:
- ✅ Используется nonce в каждом сообщении WebSocket
- ✅ TTL nonce = 10 минут
- ✅ Rate limiting на IP адрес
