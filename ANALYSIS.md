# SIEM-Agent: Анализ проблем и рекомендации

## 📋 РЕЗЮМЕ
Проект содержит три основных проблемы. Первая уже решена. Вторая требует добавления логики в корреляционный движок. Третья требует проверки и доработки веб-интерфейса.

---

## ✅ ПРОБЛЕМА 1: Разные базы данных

### Статус: РЕШЕНА

**Текущее состояние:**
- `main_server.cpp` использует функцию `sharedDbPath()` для указания пути БД
- `main_desktop.cpp` использует ту же функцию `sharedDbPath()`
- Оба приложения обращаются к одному файлу: `~/.local/share/SIEMAgent/siemagent.db`

**Доказательство:**
```cpp
// main_server.cpp (строка 21)
static QString sharedDbPath() {
    QString base = QDir::homePath() + "/.local/share/SIEMAgent";
    QDir().mkpath(base);
    return base + "/siemagent.db";
}
// Используется: dbService.openWithPath(sharedDbPath());

// main_desktop.cpp (строка 30)  
static QString sharedDbPath() {
    QString base = QDir::homePath() + "/.local/share/SIEMAgent";
    QDir().mkpath(base);
    return base + "/siemagent.db";
}
// Используется: dbService.openWithPath(sharedDbPath());
```

**Вывод:** 
✓ Администратор, созданный в веб-интерфейсе с измененным паролем, **БУДЕТ видим в десктопе** с новым паролем.

## ⚠️ ПРОБЛЕМА 2: Логика создания алертов

### Статус: ТРЕБУЕТ ДОРАБОТКИ

**Текущее состояние:**
1. События создаются ТОЛЬКО через WebSocket ✓ (правильно)
2. WebSocketWorker обрабатывает входящие события:
   ```cpp
   // WebSocketWorker.cpp - строка 149
   if (m_dbService && m_dbService->createEvent(event)) {
       emit eventReceived();
       broadcastJson(...); // трансляция всем клиентам
       if (m_correlationEngine) {
           m_correlationEngine->analyze(event); // ← отправляем на анализ
       }
   }
   ```

3. CorrelationEngine создает алерты ТОЛЬКО по правилам корреляции:
   ```cpp
   // CorrelationEngine.cpp - analyzeThreshold()
   if (count >= rule.threshold) {  // Проверяет только пороговые правила
       if (!isOnCooldown(rule.id, event.deviceName)) {
           Alert alert = buildAlert(rule, event.deviceName, event);
           m_db->createAlert(alert);
       }
   }
   ```

**ОТСУТСТВУЕТ ЛОГИКА:**
- ❌ Автоматического создания алертов для событий с `severity = "high"` или `"critical"`
- ❌ Такие события должны создавать алерты НЕЗАВИСИМО от правил корреляции

### Решение

Необходимо добавить в `CorrelationEngine::analyze()` проверку severity и создание алерта:

```cpp
// В CorrelationEngine.cpp, в конце функции analyze()
void CorrelationEngine::analyze(const Event &event) {
    // ... существующий код ...
    
    // ДОБАВИТЬ: Автоматическое создание алерта для high/critical событий
    QString sev = event.severity.toLower();
    if (sev == "high" || sev == "critical") {
        // Создаем автоматический алерт для события с высокой серьезностью
        Alert alert;
        alert.id = QUuid::createUuid().toString(QUuid::WithoutBraces);
        alert.title = "Высокоприоритетное событие: " + event.eventType;
        alert.description = "Автоматически созданный алерт для события с высокой серьезностью\n"
                          "Устройство: " + event.deviceName + "\n"
                          "Тип события: " + event.eventType + "\n"
                          "Действие: " + event.action + "\n"
                          "Лог: " + event.rawLog;
        alert.severity = event.severity;  // Наследуем серьезность события
        alert.status = "open";
        alert.deviceName = event.deviceName;
        alert.triggeredAt = event.timestamp.isValid() 
                          ? event.timestamp 
                          : QDateTime::currentDateTimeUtc();
        alert.ruleId = "";  // Это не алерт по правилу
        alert.assignedTo = "";
        alert.comment = "Авто-создан по severity=" + event.severity;
        
        if (m_db->createAlert(alert)) {
            qDebug() << "[CorrelationEngine] Auto-alert created for event:"
                     << event.deviceName << "severity=" << event.severity;
            emit alertCreated();
        }
    }
}
```

## 📱 ПРОБЛЕМА 3: Полнота функциональности веба

### Статус: ТРЕБУЕТ ПРОВЕРКИ И ДОРАБОТКИ

**Существующие страницы в веб-интерфейсе:**

| Страница | Файл | Функции |
|----------|------|---------|
| **Dashboard** | `dashboard.js` | Основная статистика, граф активности, топ устройства |
| **Events** | `events.js` | Список событий, просмотр, обновление |
| **Alerts** | `alerts.js` | Список алертов, фильтр по статусу, изменение статуса |
| **Users** | `users.js` | Управление пользователями (создание, редактирование, удаление) |
| **Rules** | `rules.js` | Управление правилами корреляции (CRUD операции) |
| **Settings** | `settings.js` | Смена пароля, управление БД, экспорт отчетов |

### Проверка функциональности:

✓ **Dashboard** - полнота
- Статистика по событиям и алертам
- График активности последних 7 часов
- Топ устройств по количеству событий
- Состояние WebSocket соединения

✓ **Events** - полнота  
- Список всех событий с пагинацией
- Фильтр по severity
- Просмотр подробностей события
- ~~Возможность создания события~~ (правильно, только через WebSocket)

✓ **Alerts** - полнота
- Список всех алертов
- Фильтр по статусу (открытые, изучаются, закрытые)
- Изменение статуса алерта (открыть → изучается → закрытый)
- Просмотр описания и деталей

✓ **Users** - полнота
- Список пользователей
- Создание новых пользователей
- Редактирование (активация, смена роли)
- Удаление пользователей
- Обязательное изменение пароля для новых пользователей

✓ **Rules** - полнота
- Список всех правил корреляции
- Управление правилами (создание, редактирование, удаление)
- Включение/отключение правил
- Два типа правил: threshold и correlation

✓ **Settings** - полнота
- Смена собственного пароля
- Статистика БД (количество событий и алертов)
- Очистка события и алертов (только для админа)
- Экспорт отчетов (CSV/JSON)

### Дизайн веба:
- Использует современный CSS с переменными (`--text-primary`, `--danger`, и т.д.)
- Адаптивный дизайн (мобильные устройства)
- Система компонентов (модалки, тосты, фильтры)
- Темизация (возможно переключение темы)

### Рекомендации по веб-интерфейсу:

1. **Минимальные улучшения:**
   - Проверить отображение пользователя в Settings
   - Добавить аватар/инициалы пользователя в навигации
   - Улучшить отображение статуса WebSocket (зеленый/красный индикатор)

2. **Функциональные улучшения:**
   - Страница профиля пользователя 
   - История изменений статусов алертов
   - Возможность добавления комментариев к алертам
   - Расширенный поиск по событиям и алертам

3. **Дизайн-дефекты:**
   - Проверить контрастность текста для WCAG доступности
   - Улучшить spacing и padding в некоторых компонентах
   - Добавить иконки для лучшего визуального ориентирования
